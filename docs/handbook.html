Invisible — a local assistant on a capture-excluded overlay

It listens to a live conversation, transcribes it, and streams model-generated advice onto a transparent window that screen capture cannot see. Nothing leaves the machine — no audio, no transcript, no model call.

Electron + LangGraph.js Windows 11 x64 only no HTTP API whisper.cpp :8178 Ollama :11436 Qdrant :6333

Before you use this

Recording a conversation without the other party's consent is unlawful in two-party-consent jurisdictions — including California, Washington, Illinois, and most of the EU. The design reflects that: audio is never written to disk, the transcript lives only in memory capped at 40 turns, and one keystroke (Ctrl+Shift+X) stops capture, clears state, and hides the overlay.
Using this in a live interview is deception of the interviewer. Most employers treat it as grounds for rescinding an offer, and some proctored platforms detect overlay or process anomalies. The software does not enforce that judgement; it is yours to make.

What the capture exclusion does and does not do

setContentProtection maps to WDA_EXCLUDEFROMCAPTURE on Windows. It defeats Zoom, Teams, Meet, OBS, Game Bar, and PrintScreen. It does not defeat a phone camera pointed at the screen, and it does not hide the process from software that enumerates running executables.

What it is

The shape of the thing

microphone ─┐                                    ┌─ Qdrant (your corpus)
            ├─ Silero VAD ─ whisper.cpp ─ triage ┤
system audio┘                                    └─ Ollama ─ overlay

Speaker identity comes from which capture chain the audio arrived on, so no diarization model is needed. Your own speech is transcribed but never answered.

Measured end to end: ~673 ms from end of question to first visible word — 384 ms VAD close, 113 ms transcription, 60 ms retrieval, 164 ms to first token.

Flow 1 of 4

From sound to an answer on screen

START ─► transcriber ─► triage ─┬─(respond)─► retriever ─► generator ─► END
                                └─(ignore)──────────────────────────────► END

Four nodes, injected rather than imported, so the routing is testable without a model, a vector store, or a speech recogniser.

  1. Capture and VAD

    Two chains — microphone and system audio — at 16 kHz mono, the rate whisper wants, so Chromium resamples every source through a proper anti-alias filter. Silero v5 closes an utterance after redemptionMs of silence: 640 ms in interview mode, 384 ms in meeting mode, because measured interview questions carry 500–1000 ms mid-question hesitations. Utterances under 192 ms are discarded as coughs and keyboard clicks.

  2. Speculative transcription

    After six consecutive silent frames mid-utterance, the audio so far is transcribed while the redemption window is still open. If the utterance then ends in that same silence, the draft is reused and both the whisper cost and the rest of the window vanish from the latency path.

  3. transcriber

    whisper.cpp over HTTP on 127.0.0.1:8178. One model instance; at most 8 utterances may queue, and beyond that the oldest is dropped and counted — a growing backlog means the overlay is answering a question from a minute ago, which is worse than missing one.

  4. triage

    Decides respond or ignore. Your own speech routes to ignore here; that is where the "never answers you" rule lives.

  5. retriever

    Qdrant, top 4, cosine score threshold 0.6.

  6. generator

    Ollama, qwen2.5-coder:14b-instruct-q4_K_M, temperature 0.2, numPredict: 200 to cap a runaway answer, keepAlive: 30m so the 9 GB model stays resident between questions. Tokens stream to the overlay as they arrive.

Why the retrieval threshold is 0.6, not 0.45. nomic-embed-text scores any two English sentences highly — measured on a real corpus, a pure algorithms question still pulled a résumé story at 0.51. With the model's task prefixes applied, genuine hits land at 0.62–0.72 and irrelevant ones peak around 0.56. The threshold exists to exclude, not to maximise recall: the overlay shows four lines, and a marginal match displaces real answer.
Flow 2 of 4

What it remembers, and for how long

  • 40 turns retained in graph state; older turns are dropped.
  • 8 turns of dialogue are sent to the model, so follow-up questions resolve.
  • Turns falling out of that window are folded into a running summary of under 80 words, refreshed every 6 new turns.
  • Nothing is written to disk. Not audio, not transcript. The cap is memory policy, not a retention policy — there is no store to retain into.

Ctrl+Shift+K clears the transcript. Ctrl+Shift+X — panic — stops capture, clears state and hides the window in one press with no confirmation dialog; Ctrl+Shift+' resumes capture afterwards.

Flow 3 of 4

Grounding answers in your own material

Drop markdown into corpus/ — résumé, project write-ups, prepared STAR stories, notes on the company — then npm run ingest.

Write one idea per ## section. Chunks split on headings, so a section that is one coherent story retrieves cleanly while a section covering four jobs retrieves as mush. Sections longer than 1200 characters are split again on paragraph boundaries.

INVISIBLE_CORPUS_DIR points the ingester at notes kept outside the repo — an Obsidian vault, for instance. Nothing in corpus/ is committed. Without a corpus the app works fine; answers are simply less specific.

Flow 4 of 4

The IPC surface — this app’s API

Invisible has no HTTP API and therefore no Swagger. It is a desktop application; its interface is Electron IPC plus a set of global shortcuts. The equivalent contract lives in src/main/channels.js.

Every channel name is in one file, and both preloads use it as an allow-list. A compromised renderer cannot reach an unlisted channel. Adding a channel means adding it there — nowhere else grants access.

Operations

Running it

Verify Docker can reach the GPU before anything else — if this does not print your GPU, nothing below works at a usable speed:

docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi
npm install                 # also vendors the VAD and ONNX assets
npm run services:up         # Ollama + Qdrant containers, GPU-enabled
npm run ollama:pull         # answer model, 9 GB
npm run embed:pull          # embedding model, 274 MB
npm run fetch-whisper       # whisper binary + model, 2.3 GB
npm run dev

Then press Ctrl+Shift+, and read the Setup panel. It probes every dependency and prints the exact command for anything missing. It never changes anything itself — every fix is a command you run.

Headphones are mandatory. Through speakers the microphone re-captures system audio and every remote utterance is transcribed twice. Requirements otherwise: Windows 11 x64, an NVIDIA GPU with 12 GB+ VRAM (developed on a 4090), Docker Desktop with the WSL2 backend and GPU passthrough, Node 24+, and ~13 GB of disk.

Installer

npm run dist     # release/Invisible Setup 0.1.0.exe, about 107 MB

It bundles app code only — place bin/ and models/ beside the installed Invisible.exe, or copy them from a source checkout. The installer is unsigned; SmartScreen warns on first run.

Or via the devkit: powershell -File $dk\invisible\devup.ps1 -CheckOnly -Test

Verification

Testing

npm test          # node --test "test/**/*.test.js"
npm run replay    # scripts/replay-interview.js — drive the graph from a fixture

The graph nodes are injected, so buildGraph is tested with four stub functions and no infrastructure at all. replay-interview.js is the integration path: it feeds a recorded transcript through the real graph, which is how latency and retrieval quality get measured without holding a live conversation.
